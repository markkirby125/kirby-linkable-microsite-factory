## 4.1 First-`2%` Token Centerpiece Annotation & Minimal-Fluff Tool Front Ends
*(Directional / single-source observation from `audiotext.com` & Content Warehouse API Leak commentary; live Google annotation weights are unobservable.)*
1. **Place the Primary Tool in the First `2%` of Tokens:** On single-page utility microsites (`audiotext.com`: `~50 → ~8,000` clicks/day), place the giant primary interactive control (`upload button`, `calculator`, `tool canvas`) + clear friction-removal cue (`"no sign up"` / `"free tool"`) immediately above the fold in Viewport 1.
2. **Prevent Token Dilution:** Strip unnecessary introductory essays above or around the utility; excessive narrative copy dilutes entity/action focus across the document's opening tokens and triggers pogo-sticking. Keep supporting instructions compact below the tool.

## 4.2 High-DR Organic Link Flywheel & Strict GSC Account Isolation
1. **Verify Crawlability Before Scaling Page Count:**
   - Confirm initial indexation and crawl health in Google Search Console on the first batch (`~70` pages) before expanding directory size (`→ 139+` pages) — never dump thousands of unverified pages simultaneously (`../../kirby-seo-deployment/SKILL.md` Module 7 §7.2).
2. **Editorial Internal Linking Across Owned Properties:**
   - Connect genuinely distinct, disclosed niche utilities only where editorial relevance serves readers (never construct hidden PBN rings or manipulate anchor text — comply strictly with `../../kirby-seo-deployment/SKILL.md` Module 7 §7.3 and `../../kirby-saas-syndicate/SKILL.md` FTC common-ownership disclosure rules).
3. **Separate GSC Accounts Across Independent Experiments:**
   - Following `../../kirby-seo-telemetry/SKILL.md` Module 5 §5.11 (GSC Air-Gapping) and Hawley's `25` separate Gmail GSC accounts isolation pattern, keep unrelated experimental domains in separate Google Search Console properties so algorithmic demotions on one test property never cluster or contaminate core business domains.
